## 三、踩坑大集合（沉淀给未来 AI / 项目协作者）

### 踩坑 1：spec 字面 vs 产品意图脱节

- **问题**：cc 5/22-23 全程在 ode_loss rollout 任务上验证 LNN，4 个训练方案 daemon shuffle ≈ 0
- **真因**：spec 写"ODE rollout"是**训练任务**，产品真实需要"online intent prediction"
- **教训**：cc 必须周期性追问产品意图，不能只跟 spec 字面跑
- **沉淀**：mycc `feedback_user_intent_anchoring`

### 踩坑 2：daemon 1fps 不是 daemon 配置问题，是 py-feat 物理瓶颈

- **问题**：5/22 cc 配 daemon target_fps=30，jsonl 实际只 1fps
- **真因**：摄像头 30fps 采集但 py-feat 单线程处理 1fps，丢帧
- **教训**：fps 升级不只是数据采集层的事，要看完整 pipeline
- **沉淀**：mycc `feedback_pyfeat_singlethread_bottleneck`

### 踩坑 3：threading 多 worker AUExtractor 100% AU 0 bug

- **问题**：threading 2 worker 启动后 jsonl 100% face=true 但 raw_au 全 0
- **真因**：AUExtractor 用 `cv2.imwrite(tmp_dir/frame_{counter%3}.jpg)` + `detect_image()`，多 worker 同 tmp_dir 文件互相覆盖 → py-feat 读到错文件
- **不是**：py-feat 模型 thread-safe 问题（cc 之前错误假设）
- **修复**：multiprocessing 路径每 worker 独立 PID-isolated tmp_dir
- **沉淀**：mycc `feedback_pyfeat_tmpdir_race`

### 踩坑 4：multiprocessing pool fps 没翻倍

- **问题**：mp 2 worker 实测 1.07fps（不是预期 1.5-2fps）
- **真因**：CapturedFrame numpy ~3MB 跨进程 pickle 开销 + py-feat 单帧 1.5-3s 硬下限
- **教训**：worker 多不等于 fps 多，序列化开销可能吃掉并行收益
- **解法**：v0.2 评估 shared memory（mmap）传 numpy frame 而非 pickle
- **沉淀**：mycc `feedback_mp_pickle_overhead_eats_parallelism`

### 踩坑 5：codex 测试 mock vs 真库走眼

- **问题**：threading 路径 codex 6 测试全过，但用 mock 没暴露 tmp_dir 文件冲突
- **教训**：第三方库（py-feat / torch / cv2）的多 worker 模式必须用真库测试，不能信 mock
- **修复**：cc 主线写 spike test 用真 AUExtractor 验证 2 worker 输出
- **沉淀**：mycc `feedback_codex_mock_test_blindspot`

### 踩坑 6：M5 Air macOS TCC 摄像头授权

- **问题**：cc 在 Claude Code sandbox 调 osascript 启 Terminal 无 WindowServer 上下文，daemon 起不来
- **教训**：macOS 摄像头授权依赖 GUI 前台 Terminal，cc 无法绕过
- **解法**：必须川哥手动在 Terminal.app 跑 start-daemon.sh
- **沉淀**：mycc `feedback_macos_tcc_camera_terminal_required`

### 踩坑 7：start-daemon.sh `set -u` race condition

- **问题**：`EXISTING_PID=$(lsof...)` 在 set -u 下偶发 unbound variable
- **真因**：lsof race + zsh ${var?} 解析差异
- **修复**：`EXISTING_PID=""` 显式初始化 + `${EXISTING_PID:-}` 兜底
- **沉淀**：mycc `feedback_bash_set_u_lsof_race`

### 踩坑 8：daemon V0.1 preflight target_fps ≤ 5.0 硬限制

- **问题**：daemon_config.preflight_check 写死 V0.1 spike 期 5fps 上限，ADR-028 升 30Hz 必报错
- **修复**：上限改 60.0 + 配套 disk budget 提到 20GB/day + retention 2h
- **教训**：spike 期硬编码限制必须配套升级，不能只升一个参数
- **沉淀**：mycc `feedback_daemon_preflight_legacy_limit`

### 踩坑 9：shuffle_ratio 在 1Hz 数据上物理可达性

- **问题**：daemon 1Hz shuffle_ratio 在 4 个训练方案都 ≈ 0
- **真因**：1Hz 信号每秒 AU 变化小，shuffle 与原序列差异天然小 → shuffle test 不适合 1Hz
- **教训**：metric 设计要考虑数据采样率的物理特性
- **沉淀**：mycc `feedback_shuffle_ratio_sampling_rate_dependency`

### 踩坑 10：rare AU fixed_bottom 钦定违背双数据集实证

- **问题**：gemini 14 钦定 AU28/AU43 是罕见微表情，但川哥 14 天 + VEATIC 10 vid 实测都不是
- **真因**：FACS 临床文献"罕见"≠ 实际数据集频率
- **修复**：V0.3 D' fixed_bottom 改 AU07/AU10（跨数据集共识）+ V0.4 加 TOP_COLLAPSE_RATIO 防整体崩盘 false green
- **沉淀**：mycc `feedback_facs_theory_vs_real_data`
