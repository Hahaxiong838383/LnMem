# ADR-009: 拒绝 RAG / 长上下文捷径，坚守 LNN-FIRST 哲学

**状态**：accepted（哲学级最终决定，川哥钦定）
**日期**：2026-05-16
**决策者**：川哥（最终拍板 Q2=A）+ cc（呈现选项）+ gemini（提出 RAG 捷径质疑）
**触发**：gemini 调研第 4 点 "工业界 Pi/Character.ai 规模化早期均极力避免端侧参数更新，全靠上下文与 Prompt 维持连贯记忆。过早死磕元学习与 FL 会陷入工程泥潭"

---

## 背景

gemini 对 X 方案 5 阶段路线提出尖锐质疑：工业界主流（Pi / Character.ai）在 M3+ 规模化阶段**避免**端侧持续学习，改用 RAG + 长上下文 + Prompt 工程。理由是工程稳定 + 收敛快 + 灾难性遗忘风险低。

如果 LnMem 借鉴这条捷径：
- M3 前不做联邦学习 / hypernetwork / 元学习
- 改用：每用户 vector DB 存历史 events → 推理时 RAG 检索 → Prompt 注入 LLM
- 工程量大幅降低
- 但**完全偏离 LnMem 项目哲学**

## 决策

**拒绝 RAG / 长上下文捷径，坚守 LNN-FIRST 哲学。**

不接受 gemini 第 4 点建议（但保留其作为对照警告）。

## 决策依据（哲学 + 商业）

### 1. lnn-first.md §1.1 项目命名即承诺

> "LnMem 的全称是 **L**iquid **n**eural **Mem**ory。如果记忆系统不以 LNN 为内核，这个名字就是欺诈，整个项目失去差异化定位。
> 竞品（Mem0 / Zep / Letta / mem-agent / Graphiti）全部用 LLM + 向量库做记忆，本质都是**离散文本游戏**。LnMem 的唯一壁垒是把记忆建模为**连续时间动力学系统**——LLM 只做"重要性裁判"和"语言渲染"，不做记忆本身。"

走 RAG 捷径 = **变成另一个 Mem0** = 项目失去差异化。

### 2. product-definition.md §10.1 不可妥协 6 项

> 技术不可妥协 2: "多时间尺度 LNN 心智核心（哪怕只有两层）"
> 产品不可妥协 4: "per-user 个性化栈"（LNN 原生轻量三件套，**不是 RAG**）

如果走 RAG 捷径，违反 §10.1 第 2 + 4 项。这是**封版承诺**，不允许。

### 3. 工业界对标的局限

gemini 提的 Pi / Character.ai 都是 **LLM-based** 系统，它们的差异化是"角色扮演 / 对话流畅"，**不是"真懂你"**。RAG 对它们够用是因为它们承诺的就是"chat experience"。

LnMem 承诺的是 "陪你数年 + 跨场景同一个它" — 这需要**连续心智状态**，RAG 不是连续状态。

### 4. 工程困难 ≠ 方向错

gemini 说"过早死磕 FL/元学习陷入泥潭" — 这是工程预警，**不是方向否定**。
解决方法是**分阶段降低工程难度**（ADR-007 base 真人化 → ADR-008 User-LoRA → M3+ 联邦），不是**改方向**。

## 选项与对比

| 选项 | 优点 | 缺点 | 拍板 |
|---|---|---|---|
| **A. 坚守 LNN-FIRST（不 RAG）** | **差异化清晰 + 项目哲学一致** | 工程难度高 | ✅ 川哥钦定 |
| B. M3 前插 RAG 捷径 | 工程简单 | **失差异化**（变 Mem0） | ❌ |
| C. RAG + LNN 并存（混合） | 中庸 | 复杂度叠加 + 哲学混乱 | ❌ |

## 与 ADR-001 一致性

ADR-001 (Route B Single-Founder AI Mode) 已确立 "**坚定 LNN-FIRST 单创业者模式**"，本 ADR 是其延伸应用。

## 后果

### 正面
- 项目哲学锁死，不再被工业界对标动摇
- 差异化清晰：LnMem ≠ Mem0 / Pi / Character.ai
- 长期技术壁垒（连续时间动力学是稀缺能力）

### 负面 / 风险
- M3-M5 工程难度比 RAG 路径高 5-10x
- 可能因技术难度推迟商业化（需做好资金 / 时间预期）
- 早期用户体验可能不如 Pi 流畅（但 LnMem 不卷流畅，卷"真懂你"）

### 触发的下游决策
- ADR-007 base ckpt 真人化（消除 OOD）
- ADR-008 User-LoRA（个性化机制升级）
- M4 联邦学习方案（用 Flower 框架，gemini 推荐）

## 长期反思 review 时点

3 个月后（M2 启动时）重新评估本 ADR：
- 如果 LnMem 用户增长曲线 vs Pi/Character 差距过大 → 重新审视是否需要 RAG 临时补丁（**不偏移**核心 LNN 内核）
- 如果 LNN 真人化效果好（spike-then-implement 验证） → 本 ADR 巩固

但**不再因为工程难度本身**而推翻此 ADR。

## 反对意见 / 不同看法

- **gemini 第 4 点**："工业界都用 RAG 捷径" → 川哥 + cc 共同判定：**对标错了**（Pi/Character 不解决 "真懂你"），保留为对照警告
- **cc 内心 OS**："工程难度真的会很高" → 但坚守哲学是 PoC 立项前提，工程难度通过分阶段（ADR-007/008）化解，不撤项目命题
