# LnMem 认知能力规范（v0.1.1 / 哲学一致版）

> **核心命题**：把"AI 是不是真的懂主人"作为唯一的产品成败信号。**评估方法和产品能力同构——AI 用自己的多模态理解能力评估自己的预测准确性，不打扰主人**。
>
> 本文档是 [`docs/capability-specs/`](./) 下的第一份能力规范，承载 LnMem 最核心的能力："理解主人的当下意图 + 自我评估理解的准确性"。未来同目录还会有情绪识别、主动行为等能力规范。

---

## 0. 一句话能力规范

LnMem 的认知能力 = **基于多模态信号的当下意图预测 + 基于多模态反馈的强化学习自评**。

**评估方法和产品能力同构**——AI 不靠问卷打分判断自己懂不懂主人，靠观察主人对回应的身体级反应（眼神、表情、语调、停顿）。这不是技术炫技，是产品哲学的内在要求：产品的本质就是"通过多模态信号理解人"，评估方法必须和产品能力同构，否则就是承认我们的多模态理解能力不够做评估，逻辑悖论。

**Why**（这一行是判断未来类似情况的钥匙）：评估方法定义了什么算"懂"。如果用问卷，"懂"就退化成"用户愿意在打分时给 8 分"，这是社交期望和回忆偏差的产物，不是真正的"懂"。用多模态信号，"懂"才回到本来面目——主人的身体在那一刻接纳了。

## 1. 认知能力的产品哲学锚点

### 1.1 心流监测、不打扰（最高优先级）

任何认知能力的实现，都不能违反"不打扰"。打扰主人的代价 > 任何评估精度的收益。这是最高优先级，没有例外。

具体禁区：
- ❌ 弹窗"它懂你吗 1-10 分"
- ❌ 每周问卷"上周满意度调研"
- ❌ "AI 想问你一个问题"主动 push
- ❌ 任何形式的事后主观回忆调研

允许区（不算打扰）：
- ✅ 主人主动打开"今天/我对你的新理解/记忆账本"页面
- ✅ AI 在对话流中自然说"我感觉刚才的回应可能不太对，是吗？"（详见 §5.6 主动询问兜底）

**Why**：违反"不打扰"等于违反核心承诺 5 "它会让你看见"——主人能选择看，不是被推着看。

### 1.2 多模态信号是产品本能

产品的本质就是"通过多模态信号理解人"。视觉、音频、IoT、文本、生理（未来）等多模态原料是 LnMem 的"能力地基"——所有上层能力都必须能落到多模态信号。

这条铁律的工程含义：**任何不能落到多模态信号的产品功能都是设计错误**。比如"用户主动告诉 AI 自己的偏好"这种功能违反本能——它要求主人做声明而不是 AI 自己感知，等于把"理解人"的责任推给主人。

**Why**：和 LLM + RAG 方案的本质区别就在这里。LLM 在对话时检索过去；LnMem 在永远在线的连续时间状态里持有当下，**通过多模态信号主动写入和评估**。如果丢掉多模态本能，LnMem 就退化成普通 RAG 应用。

### 1.3 我们的差异化承诺（v0.3.x 加第 6 项）

v0.3 §1.3 五大核心承诺基础上，认知能力规范引入**第 6 个差异化承诺**：

> **6. 评估机制本身就是产品体验的一部分**——我们坚决不用问卷、弹窗、评分这种打断式评估。评估必须像呼吸一样自然，从主人的真实反应中浮现。这不是"我们没做评估"，而是"评估溶解在交互里"。

这条承诺对外解释（投资人/媒体语言）：

> "你不会被你的 AI 伙伴问'你今天过得怎么样'。它通过看你皱眉的频率、听你呼吸的节奏、感受你停顿的长度，来知道自己懂不懂你。"

**Why**：第 6 项不是技术参数，是产品哲学。和其他 5 项一样进入不可妥协 6 项的范畴（建议 v0.4 把这条加到 product-definition.md §10.1，详见本文 §7.3 联动清单）。

## 2. 八层认知架构在意图预测中的角色

### 2.0 产品语言（七层）↔ 工程语言（八层 0-8）映射表

LnMem 同时存在两套术语：投资人/产品语言用"七层"，工程文档用"八层 0-8"。本节给出权威映射，避免混乱。

**权威工程编号（本文档 + 后续所有工程文档统一遵循）**：用 [`README.md`](../../README.md) §核心架构 的 0-8 编号。

| 产品语言（v0.3） | 工程编号（README 0-8） | 1:1 / 跨层 | 涌现能力 |
|----------------|---------------------|-----------|---------|
| 多模态感知 | Layer 0 | 1:1 | — |
| 万能语法 | Layer 1 | 1:1 | — |
| 当下意识 | Layer 2 (L1 LNN τ≈秒) | 1:1 | 工作记忆 |
| 短期叙事 | Layer 3 (L2 LNN τ≈分钟) | 1:1 | 注意力 |
| 事件分割 | Layer 4 | 1:1 | — |
| 情景记忆 | Layer 5 (Graphiti KG) | 1:1 | — |
| 巩固机制 | Layer 6 (CLS Consolidation) | 1:1 | — |
| 人格记忆 | Layer 7 (L3 个性化三件套) | 1:1 | — |
| 用户治理 | Layer 8 (用户可见层) + 跨层治理协议 | 1:N（见自检 §9.1.4） | 共生协议 |

**涌现能力**（不是新增层，是跨多层协作产生的能力）：
- **意图预测**：跨 0-7 全栈协作产生（详见 §2.1 总体协作机制）
- **共情回应**：跨 0/2/3/7 协作产生（多模态感知 → 工作记忆 → 短期叙事 → 人格记忆）
- **元认知**（AI 知道自己懂没懂）：本文档 §5 描述的"反馈采集 → 自我修正"循环，跨 0-8 全栈
- **共生协议**（用户编辑/删除记忆 → 系统更新行为）：以 Layer 8 为入口，反向触发 Layer 5/6/7 更新

**注意**：[`memory-architecture.md`](../memory-architecture.md) 内部使用 L1/L2/L3 三层 LNN 编号（指 README Layer 2/3/7），这是工程视角的细化标签——不要和 README 的 Layer 1-3 混淆。本文档以下统一用 Layer 0-8。

**Why**：两套术语并存是产品文档的现实——投资人/老板用产品语言，工程师用工程语言。映射表让"L4 程序记忆 / L5 POMDP / L7 共生协议"这种产品语言不再造成跨文档翻译负担。

### 2.1 总体协作机制：每层贡献什么类型的信号到意图预测

意图预测不是单一层的工作，是 0-7 全栈协作。每层产出特定类型的信号，由 Layer 5/6/7 综合决策。

| 层 | 贡献的信号类型 | 时间尺度 | 在意图预测中的"问什么" |
|----|-------------|---------|-------------------|
| L0 感知 | 原始多模态嵌入 | 实时 (ms) | "现在外部世界是什么样" |
| L1 Parser | 槽位填充 + 置信度 | 100ms | "刚才发生的事情如何用 20 槽描述" |
| L2 工作记忆 | 当下情绪/注意力状态 | 秒 | "主人此刻的内心状态" |
| L3 短期叙事 | 当前事件的"完成度"判断 | 分钟 | "这一段经历是不是一个完整 episode" |
| L4 事件分割 | 是新事件还是延续 | 事件级 | "现在该不该写入长期记忆" |
| L5 情景记忆 | 历史相似事件的检索结果 | 时间锚定 | "类似情境上次主人怎么样" |
| L6 巩固 | 长期模式提取 | 长期 | "这种情况主人通常喜欢什么" |
| L7 人格记忆 | per-user 偏好向量 + τ 偏置 | 终身 | "主人是怎样的人" |
| L8 治理 | 用户对历史预测的反馈日志 | 跨时间 | "主人之前对类似预测的态度" |

**意图预测的最终决策**：发生在 L7 的偏好向量 + L5 的检索结果 + L2 的当下状态三者交叉点上，由一个轻量推理头（M2 末实现）综合输出"现在主人想要什么"的概率分布。

**Why**：把"意图预测"看成"全栈协作产生的涌现能力"而不是"某一层的功能"，是 LnMem 区别于"训练一个意图分类器"的本质——意图分类器是离散的、固定时刻的、单视角的；LnMem 的意图预测是连续的、永远在线的、多视角融合的。

### 2.2 Layer 0 多模态感知层 — 在意图预测中的角色

**工程实现**：见 [`memory-architecture.md`](../memory-architecture.md) §2 / [`README.md`](../../README.md) "0 · 多模态感知层"

**在意图预测中的角色**：把摄像头/麦克风/IoT/文本异构原料统一成"模态嵌入 + 时间戳"流——所有上层的"输入材料"。L0 不准确，下游全部失真，意图预测崩盘。

**编码的信号示例**：
1. 视觉：面部表情（喜/怒/哀/惊/疲惫）、姿势（瘫坐/直立/紧绷）、注意力方向（盯屏幕/看 AI/低头）
2. 音频：声纹（识别说话人）、语调（升/降/平）、语速（急/缓）、呼吸节奏
3. IoT：位置（家/车/办公室）、设备状态（车启动/灯打开）、环境光线/温度
4. 文本：用户主动输入

**缺位会导致**：意图预测退化到"只看用户说了什么"，丢失"用户是怎么说的"。例如：主人说"放点轻松的"——文本只看到"轻松"，但视觉看到的"瘫坐+疲惫表情"才是真正的意图修饰。L0 缺位 → 推荐变成爆裂音乐。

### 2.3 Layer 1 万能语法 Parser → EventTensor 20 槽（★核心 IP★）

**工程实现**：见 [`memory-architecture.md`](../memory-architecture.md) §5.1 / [`README.md`](../../README.md) "1 · 万能语法 Parser"

**在意图预测中的角色**：把多模态包压缩成 20 槽固定 schema——这是认知系统的"标准件"，所有意图预测算法的物理基础。20 槽是预测算法的"特征向量"，没有它每层用各自格式，无法做跨时间检索。**这是 LnMem 的核心 IP，意图预测能力的天花板取决于 Parser 质量**。

**编码的信号示例**：
1. P0 必填槽：who（谁）、when（何时）、where（哪里）、what（做什么）
2. P1 检索主键：mood（情绪）、intent（意图）、object（对象）
3. P2 时态推理：duration（持续时长）、frequency（频率）、boundary（事件边界）
4. P3 仅向量化：长尾叙事走 Overflow Capsule

**缺位会导致**：意图预测无"特征向量"，退化到端到端黑盒——失去解释性、失去跨时间检索、失去用户治理（治理的最小单位是槽位）。M1 末有红区门槛：槽位填充率 P0 < 60% 直接红区。

### 2.4 Layer 2 L1 LNN（τ≈秒，64 neurons）— 当下意识

**工程实现**：见 [`memory-architecture.md`](../memory-architecture.md) §3.1 / [`README.md`](../../README.md) "2 · L1 LNN"

**在意图预测中的角色**：承载"现在正在发生什么"——秒级敏感度，捕获瞬时情绪、意图、注意力。**它就是 AI 的"当下意识"，提供意图预测的"现在时态"信号**。

**编码的信号示例**：
1. 主人语速从平稳变急促（0.3 秒内 LNN 隐状态变化）
2. 主人皱眉到放松的过渡（瞬时情绪转折）
3. 主人对话中的"停顿—接续"节奏
4. 注意力突然转移（看手机 → 看 AI）

**缺位会导致**：AI 失去"当下感"，退化成传统聊天机器人——必须等下一个 token 才更新，慢一拍，无法在主人皱眉时即时调整。

### 2.5 Layer 3 L2 LNN（τ≈分钟，32 neurons）— 短期叙事

**工程实现**：见 [`memory-architecture.md`](../memory-architecture.md) §3.2 / [`README.md`](../../README.md) "3 · L2 LNN"

**在意图预测中的角色**：承载"这一小段时间在发生什么"——比 L2 更慢的演化，对应"一通对话""一段路程""一顿饭"这种自然事件单元。**给意图预测提供"近期处境"信号**。

**编码的信号示例**：
1. 5 分钟对话收敛到的状态向量（如"想要安静的、近郊的、不需做攻略的地方"）
2. 一段路程的整体情绪轨迹（出发愉悦 → 中途焦躁 → 到达放松）
3. 一顿饭的主题演变（工作话题 → 私人话题 → 共同回忆）
4. 一个晚间的"动机渐变"（想看剧 → 太累 → 只想躺着）

**缺位会导致**：L2 直接接事件分割会因为太敏感把"一通对话"切成 50 个事件，KG 被噪声淹没，意图预测的"近期上下文"维度坍缩。

### 2.6 Layer 4 事件分割门控

**工程实现**：见 [`memory-architecture.md`](../memory-architecture.md) §4.2 / [`README.md`](../../README.md) "4 · 事件分割门控"

**在意图预测中的角色**：判断"刚才这段是不是一个完整事件，要不要写入长期记忆"——决定 KG 写入频率和颗粒度。**给意图预测提供"事件边界"信号**——AI 知道"现在是新场景开始"还是"延续刚才的话题"。

**编码的信号示例**：
1. 沉默 > 30 秒 → boundary 触发
2. 物理位置切换（车 → 家）→ boundary 触发
3. 主语切换（"我在工作" → "我在想孩子"）→ boundary 触发
4. 槽位变更率突变（mood/object 同时变）→ boundary 触发

**缺位会导致**：要么写得太少（KG 一天 3 条记忆），要么写得太多（KG 一天 500 条片段噪声），都让"上周三晚上"这种检索失效。M2 末有红区门槛：F1 < 0.3。

### 2.7 Layer 5 情景记忆（Graphiti KG bi-temporal）

**工程实现**：见 [`memory-architecture.md`](../memory-architecture.md) §5.2 / [`README.md`](../../README.md) "5 · L2 情景记忆"

**在意图预测中的角色**：以"何时-何地-与谁-做了什么"为单元的事件库——支持时间锚点检索。**给意图预测提供"历史相似情境的处理结果"信号**。

**编码的信号示例**：
1. "上周三晚上和老张吃饭"完整 episode（时间锚定 + 实体 + 主题）
2. "三个月前类似情境主人选择了什么"
3. "主人提到 X 时通常的后续行为"
4. "本周 vs 上周的情绪 episode 分布对比"

**缺位会导致**：AI 只能用最近几轮对话回答，违反核心承诺 1 "它会记得"。中文 entity F1 < 0.5 → 黄区门槛。

### 2.8 Layer 6 CLS Consolidation 巩固机制

**工程实现**：见 [`memory-architecture.md`](../memory-architecture.md) §6 / [`README.md`](../../README.md) "6 · CLS Consolidation"

**在意图预测中的角色**：每天凌晨 3 点把 L5 的事件库提炼成 L7 的语义/偏好。**给意图预测提供"模式信号"——这种情境主人通常喜欢什么的统计性结论**。

**编码的信号示例**：
1. 连续一周晚 11 点说"困了" → 固化为"bedtime_anchor=23:00 ± 30min, sleep_intent_strength=0.85"
2. 30 天内 70% 的"周末活动建议"被接受 → 学习"周末偏好向量"
3. 主人对"集体活动"持续负反馈 → 固化为"social_aversion=0.7"
4. 季节性模式（春天偏好户外 / 冬天偏好室内）

**缺位会导致**：AI 永远是"今天的它"，第 100 天不比第 1 天更懂——违反核心承诺 2 "它会变化"。合成数据污染 LoRA 是这一层最大的风险（M1 红区门槛）。

### 2.9 Layer 7 L3 语义/人格记忆（LNN 原生三件套）

**工程实现**：见 [`memory-architecture.md`](../memory-architecture.md) §7 / [`README.md`](../../README.md) "7 · L3 语义/人格记忆"

**在意图预测中的角色**：承载"主人是怎样的人"——周-年时间尺度的偏好、习惯、价值观、关系网络。**给意图预测提供"主人画像"信号——意图预测的最终决策权在这一层**。

**编码的信号示例**：
1. τ 偏置：什么类信息在主人的 LTC 状态里衰减更慢（个人化注意力）
2. FiLM 调制：什么类输入被压低/抬高权重（个人化输入透镜）
3. 槽位偏好向量：P0 槽位的个性化倾向（重视"效率"还是"关系"）
4. 长期关系图谱：哪些人在主人生活中权重高
5. 价值观偏好：环保/家庭/事业等抽象维度的向量化

**缺位会导致**：每个用户的 AI 长一个样，违反"用一个月后的它比第一天更懂你"承诺。

### 2.10 Layer 8 用户可见层 + 跨层治理协议（共生协议）

**工程实现（部分）**：见 [`README.md`](../../README.md) "8 · 用户可见层" / [`memory-architecture.md`](../memory-architecture.md) §6.1 line 324（仅 CLS 伪代码注释）

**在意图预测中的角色**：把黑箱的 L5/L7 翻译成用户可读、可编辑、可治理的 UI——**这是"它知道边界 / 它会让你看见"两条承诺的载体**。在意图预测中，**Layer 8 提供"主人对历史预测的反馈日志"——这是元认知信号最重要的来源**。

**编码的信号示例**：
1. 主人编辑"我对你的新理解"页面——直接反馈"AI 对我的理解错了"
2. 主人删除某条记忆——反馈"这件事不该作为未来推理的依据"
3. 主人在"今天"页面停留时间——隐式信号"AI 总结的今天精度如何"
4. 主人在"记忆账本"翻阅频率——隐式信号"主人对 AI 的信任度"

**缺位会导致**：AI 是黑箱，主人无法纠错，错误复利累积。**这一项是不可妥协 6 项里的产品 §6**。

**⚠️ 一致性风险（自检发现）**：[`memory-architecture.md`](../memory-architecture.md) §0-§11 的章节结构里**没有独立的"用户治理层"工程章节**。Layer 8 在 [`memory-architecture.md`](../memory-architecture.md) 里只在 §6.1 CLS 伪代码注释（line 324 `# 8. 记忆账本（用户可见 = 「记忆账本」）`）一处出现。这是真实的"产品承诺无工程对应"风险，已记入 §9.1.4 自检报告，建议未来在 [`memory-architecture.md`](../memory-architecture.md) 补一节"§5.4 用户治理协议"——这件事不在本次 commit 处理（守 product-definition.md 封版规则 + memory-architecture.md 修订需老板批准）。

### 2.11 万能语法 Parser 层为什么单独突出

虽然在 §2.3 已讲，但因为这是 LnMem 区别于"LLM + RAG"方案的本质所在，单独再强调三点：

1. **20 槽 schema 是横切 0-8 全栈的"标准件"**——没有它，每层用各自格式，无法做"上周三晚上"这种跨时间检索；意图预测无统一特征向量
2. **Parser 质量决定了认知能力的天花板**——M1 末有红区门槛（P0 槽位填充率 < 60% 直接红区），意图预测准确率受 Parser 质量直接约束
3. **Parser 是用户治理的最小单位**——主人编辑/删除记忆，操作的不是"一句话"，是"20 槽的 EventTensor 实例"。槽位级别的治理是共生协议的物理基础

**Why**：很多产品做"AI 伙伴"会跳过 schema 直接用文本——这看起来快，但失去了跨时间检索 + 用户治理两个能力。LnMem 选择"先把 schema 做对再做能力"，是对长期关系的承诺。

## 3. 完整场景演示（含反馈循环闭环）

### 3.1 场景：主人疲惫到家

**T-30s**：主人下班开车回家，车停进车库
- L0 视觉感知：面部表情疲惫（眼睑下垂 + 微皱眉）、姿势瘫坐
- L0 音频感知：哼了一声叹气
- L0 IoT：车熄火、车库门关闭、家庭场景模式触发

**T-10s**：主人开门进家，没说话直接躺沙发上
- L0 视觉：进入客厅、灯光自动调暗（家庭场景预设）、瘫沙发姿势
- L0 IoT：家门锁关闭、客厅光线传感器读数从 800 lux → 300 lux

**T+0s**：主人打开手机看了眼通知，叹气一声"哎"
- L0 音频：单字"哎"（拖长尾音 0.5 秒）
- L0 视觉：低头看手机的姿态

### 3.2 系统的"认知动作"流（Layer 0-7 协作）

```
T-30s 进车库：
  L0 → L1: parsing 多模态包到 EventTensor
    {who: 主人, where: 车库, when: T-30s, mood: 疲惫(0.85), intent: 回家, energy: 低}
  L1 → L2: 喂入 LNN 工作记忆
    L2 隐状态更新："主人能量低 + 想休息"信号增强
  L2 → L3: 短期叙事开始累积
    L3 隐状态："今晚的主题=休息恢复"

T-10s 进客厅：
  L4 事件分割检测：物理位置切换 → boundary 触发
    旧 episode "下班通勤" close → 写入 L5
    新 episode "到家" open
  L5 检索：类似处境历史 → "上次主人疲惫到家时，AI 没说话只调暗灯，主人放松了"
  L7 偏好向量查询："主人对疲惫时的陪伴偏好" → "极小行动 + 不打扰"

T+0s 听到"哎"：
  L0 音频特征 + L1 解析：tone=叹气、emotion_signal=低能量
  L2 综合所有信号：当下意图=希望被看见但不希望被打扰
  推理头综合 (L2 当下 + L5 历史 + L7 偏好) 输出意图预测：
    P(want_silence)=0.45, P(want_acknowledgement)=0.40, P(want_action)=0.15
  最终决策：低姿态 acknowledgement + 极小物理行动
  
回应生成（多模态）：
  - 文本/音频："嗯，看你姿势就知道是真累了。要不要把客厅灯再调暗一点？"
  - IoT 行动：客厅灯亮度从 30% 预降到 20%（动作未执行，等主人确认）
  - 时间安排：5 分钟内不再主动说话
```

### 3.3 反馈采集窗口（30s-2min 多模态信号 → 强化学习奖励）

系统给出回应后立即启动反馈采集窗口，主人**全程无感知**——不需要做任何额外动作。

```
T+0s：系统回应"嗯，看你姿势就知道是真累了..."

T+1s：L0 持续监测——
  视觉：主人头部微微转向 AI 方向（注意力转向 = 弱正信号 +0.2）
  音频：无回应，但呼吸节奏放缓 0.5Hz（紧张释放 = 强正信号 +0.6）
  L7 个体校准：该主人"呼吸放缓"的"懂"信号权重 = 0.85（高于群体平均）

T+3s：主人轻声"嗯..."
  音频特征：语调平稳、能量低、尾音柔和（接纳式 = 强正信号 +0.7）
  L1 Parser 解析：单字"嗯" + 接纳意图 + 不希望延展话题

T+8s：主人微笑了一下（视觉识别 +0.3）+ 没有反驳的话
  综合判断：本次预测准确度高
  L7 即时更新：偏好向量 "疲惫时极小行动陪伴" 权重 +0.05

T+30s：反馈窗口准备关闭，最后扫描——
  视觉：主人闭上了眼睛（接纳式放松 +0.4）
  音频：均匀呼吸（彻底放松 +0.3）
  L8 治理日志记录：本次预测无负反馈、无主人主动纠错

T+60s：反馈窗口正式关闭，启动事后处理：
  L5 POMDP 决策路径加权：
    "用'看见你'+'极小行动'回应疲惫" 决策路径 +0.7 累积奖励
  L6 候选模式池：
    本次成功模式 "疲惫信号 + 极小行动 = 正反馈" 进入候选（连续 5 次成功才转正写入 L7）
  L7 共生协议层即时更新：
    主人对"调灯光"这种物理陪伴的接受度 +0.05

夜间（T+8h）CLS 巩固：
  发现 30 天内 8 次类似成功 → 转正写入 L7 偏好向量
  下次类似情境（疲惫到家）AI 会更自信地选择"极小行动"路径
```

**这个闭环全程主人无感知**——没有问卷、没有评分、没有打扰。这就是 §1.3 第 6 条差异化承诺的工程具体形态。

## 4. 训练即评估：闭环强化学习的阶段演化

### 4.0 训练即评估：核心原则

**关键认知**：这套系统的训练和评估是同一个过程——每次互动都是训练步，每次反馈都是奖励信号。不是"训练完了再评估"，是"边训练边评估边迭代"。

阶段划分仍然有意义，但每个阶段的差异是**反馈信号的丰富度和密度**，不是训练方法的切换。所有阶段都跑同一套 RL 闭环，只是数据质量不同。

### 4.1 阶段 1（M0-M3）：合成数据 + LLM 模拟反馈

**主要数据源**：合成数据 pipeline（类型 1）

**反馈信号特征**：合成数据无真实多模态反馈——用 LLM 模拟反馈信号训练（虚拟主人的行为模式）

**具体做法**：
- LLM 生成"虚拟主人的多模态反应"（基于 50 个虚拟人格画像）
- 反应包含完整多模态信号（视觉描述、语音特征、时序模式）
- AI 在虚拟主人上跑 RL 闭环，学习信号-意图映射
- 风险：合成反馈分布偏移 → M1 红区门槛监控

**Why 这阶段不能直接拿真用户**：M0-M3 的 AI 还在"出生"阶段，意图预测能力差，给真用户用会损害信任，倒过来污染长期数据。先用合成数据把 AI 培育到"基础对话不出错"，才能见真用户。

### 4.2 阶段 2（M4-M6）：种子用户开始产生真实多模态反馈

**主要数据源**：3-5 个种子用户的真实交互

**反馈信号特征**：种子用户开始产生真实多模态反馈——但样本稀疏，依赖少数用户的高质量信号

**具体做法**：
- 种子用户日均 1-2 小时使用，每天产生 30-50 个反馈窗口
- 5 个用户 × 30 反馈窗口 × 30 天 = 4500 条真实反馈样本
- 这阶段的 RL 学习率必须比阶段 1 低 10x（信号稀疏，避免过拟合个别用户）
- 重点学的是"信号-意图映射的群体共性"+"个体校准的初步建立"

**Why 这阶段不扩规模**：种子用户的高质量信号比 100 个泛用户的低质量信号有价值。早期扩量等于把 AI 推到"什么都见过但什么都不深"。

### 4.3 阶段 3（M7-M12）：信号密度足够支撑稳定 RL 收敛

**主要数据源**：25-50 个 MVP β 用户

**反馈信号特征**：信号密度足够支撑稳定的强化学习收敛——每天千级反馈窗口，群体共性 + 个体差异都能学到

**具体做法**：
- 50 用户 × 50 反馈窗口/天 × 30 天 = 75000 条样本/月
- L7 个性化层每个用户独立校准（per-user τ 偏置 / FiLM / 偏好向量）
- 群体共性 vs 个体差异自动分流（信号 1 个个体出现 → L7 / 信号 30+ 个个体出现 → L6）
- 反馈信号品质监控：单一信号置信度、多信号一致性、时间衰减权重

### 4.4 阶段 4（1-3 年）：长期信号识别"主人在变化"

**反馈信号特征**：长期信号趋势能识别"主人在变化"——AI 跟着主人一起演化

**具体做法**：
- 长期偏好漂移检测：主人对某类活动的接受度从 0.7 → 0.3（半年时间）→ 触发偏好向量重学习
- 关系网络演化：主人提到 X 的频率从 daily → weekly → 标记"X 的重要性下降"
- 价值观演化：主人对环保的关注度增加 → 推荐倾向同步调整
- 共生协议成熟：用户编辑记忆的频率下降到 <1 次/月，说明 AI 自主预测准确率达成

**Why 这是终极目标**：核心承诺 2 "用一个月后的它比第一天更懂你"——一年后的它必须比一个月后更懂；三年后必须更懂。如果信号收敛后能力停滞，就是失败。

## 5. 评估方法：多模态反馈驱动的强化学习评估 ★核心★

### 5.1 评估方法论：和产品能力同构

**核心原则**：评估方法必须和产品能力同构。产品本质是"通过多模态信号理解人"——评估方法也应该是"通过多模态信号评估理解的准确性"。

**坚决拒绝传统方法**：
- ❌ 周度问卷调研（"它懂你吗 1-10 分"）
- ❌ NPS 净推荐值
- ❌ 弹窗评分
- ❌ 任何形式的事后主观回忆

**为什么坚决拒绝**：
1. 问卷本身是一种打断——违反产品"不打扰"原则
2. 主观评价不可信——受措辞、心情、社交期望影响
3. 事后回忆不准——真正的"懂"是当场的身体反应
4. 数据稀疏滞后——强化学习需要密集即时反馈

### 5.2 多模态反馈信号体系

系统通过持续观察主人对 AI 回应的**身体级反应**来评估自己。这些信号天然存在于交互中，不需要主人额外做任何事。

**强正向信号**（明确表达"懂了"）：

| 信号 | 多模态来源 | 解读 |
|------|----------|------|
| 微笑/嘴角上扬 | 视觉 | 接纳/愉悦 |
| 眼神放松/瞳孔变化 | 视觉 | 被理解的安全感 |
| "嗯""对""就是"等肯定语气词 | 语音 | 共鸣 |
| 语调放缓/呼吸加深 | 语音/生理 | 紧张释放 |
| 主动展开话题 | 行为 | 信任建立 |
| 沉默后的肯定 | 时序 | 真正被触动 |

**强负向信号**（明确表达"没懂"）：

| 信号 | 多模态来源 | 解读 |
|------|----------|------|
| 眉头紧皱/嘴角下拉 | 视觉 | 不被理解的挫败 |
| "不是""你没懂"等否定 | 语音 | 直接纠正 |
| 语速突然加快/语调上升 | 语音 | 不耐烦 |
| 中断对话/转移话题 | 行为 | 放弃沟通 |
| 长时间停顿后的妥协式回答 | 时序 | 被动接受但不满 |
| 离开场景/关掉应用 | 行为 | 极强负反馈 |

**弱信号**（需要结合上下文解读）：

| 信号 | 解读复杂度 |
|------|----------|
| 短促的"嗯" | 可能是"知道了"也可能是"不想多说"——需结合 L2 状态 |
| 沉默 | 可能是被触动也可能是无感——需结合 L3 处境 |
| 重复主人的话 | 可能是确认也可能是质疑——需结合语调 |

**Why（这套信号体系的设计原则）**：覆盖度优先于精确度。先把"系统能感知到什么信号"标完整，再迭代"每个信号怎么解读"。M0 阶段只用语音和文本（最容易实现）就足够启动 RL 闭环，视觉和生理信号在 M1+ 渐进加入。

### 5.3 强化学习反馈循环

每次系统给出回应后，启动一个**反馈采集窗口**（典型 30 秒-2 分钟）：

```
系统回应 → 反馈采集窗口启动 → 持续监测多模态信号 → 
信号分类（强正/弱正/中性/弱负/强负）→ 
反向传递到对应的预测决策点 → 
更新 L5 POMDP 的奖励信号 → 
更新 L7 共生协议的用户偏好 → 
（可选）触发 L4 程序记忆更新
```

**关键设计**：

- **奖励信号是连续的而非二元**：不是"对/错"，是 [-1.0, +1.0] 的连续值
- **不同时间窗的信号权重不同**：紧接回应后的信号权重最高，2 分钟后的衰减
- **多信号融合**：单一信号可能误读，需要至少 2 个独立模态的信号一致才高置信
- **个体差异**：同样的"嘴角上扬"在不同主人身上含义不同——L7 共生协议层负责学习每个主人的"信号-意图"映射

### 5.4 四维评估指标（自动聚合，非问卷）

不是问卷打分，是从多模态信号自动聚合：

| 维度 | 信号来源 | 测量方式 |
|------|---------|---------|
| **行动相关性** | 主人后续行为（接受/拒绝/纠正） | 强化学习奖励的累积值 |
| **意图穿透深度** | 表情/语调的"被触动"信号 | 强正信号占比（眼神放松、长沉默后肯定） |
| **时机精度** | 主动介入后的即时反应 | 介入后 5 秒内的信号极性 |
| **关系深度** | 长期信号趋势（周/月） | 强正信号比例的时间序列斜率 |

每个维度都是**自动聚合**，不需要主人做任何额外动作。

**对照 product-definition.md §13.1 的修订建议**：详见 §7.3 联动清单。

### 5.5 错误预测的处理（强化学习视角）

意图预测一定会错。强化学习视角下的处理：

**即时处理**（毫秒级）：
- 检测到强负信号（皱眉/否定）→ 立即停止当前回应路径
- 切换到"我推断错了"的修正模式
- 修正模式的回应风格：低姿态、询问式、留白多

**短期更新**（小时级）：
- 这次错误的预测决策点 → 在 L5 POMDP 中标记为低奖励
- 对应的槽位填充推断 → 降低置信度阈值
- 更新到 L7 共生协议层（per-user 即时校准）

**长期学习**（夜间 consolidation）：
- 检查这次错误是否是"个人特例"还是"模式性错误"
- 个人特例 → 仅更新 L7（不污染 L4 群体记忆）
- 模式性错误 → 触发 L4 程序记忆更新 + 触发 UniversalGrammarParser 反向训练

**关键原则**：错误推断绝不污染长期记忆——v0.3 §6.1 的"老板三重身份偏差"防护逻辑同样适用于错误信号传播。

### 5.6 评估的可验证性问题（含主动询问兜底）

诚实声明：

- **多模态信号的解读本身存在误差**——AI 把"皱眉"解读为"不满"可能错（主人可能是阳光太刺眼）
- **缓解方式**：多信号融合 + 置信度阈值 + 长期趋势平滑
- **底线兜底**：当多模态信号极不一致时（视觉说正、语音说负），系统应该**主动降级为询问式**——"我感觉刚才的回应可能不太对，是吗？"
- 这种主动询问 ≠ 问卷打分，是**对话流中自然的修正请求**——是产品哲学允许的

**主动询问兜底的触发阈值**（M0-M1 v0 规则版，M2+ 学习版）：
- 多信号置信度差 > 0.5（视觉说 +0.7、语音说 -0.3，差 1.0 → 触发）
- 同主人 24 小时内连续 3 次低置信预测 → 触发一次"我是不是有点跑偏？"
- 长期趋势异常（周强正信号比例突降 > 30%）→ 触发主人主动 check-in

**关键约束**：主动询问不能频繁——日均 ≤ 1 次/主人，违反此约束等于变相问卷。

### 5.7 工程可行性论据

可能有人质疑："这套多模态反馈听起来很重，工程上做得了吗？"

可行性论据：

1. **多模态感知能力本来就要做**——产品核心能力就是这个，评估只是复用
2. **信号定义可以从粗到细**——v0 只用语音和文本（最容易），v1 加视觉，v2 加生理
3. **L1 LNN 的状态向量本身就编码了大部分信号**——不需要额外的"信号识别模块"
4. **强化学习的奖励信号不需要 100% 准确**——长期累积下来准确率自然提升

**v0/v1/v2 渐进路线**（建议进 roadmap）：
- v0（M0-M3）：仅语音 + 文本信号 → RL 闭环跑通
- v1（M4-M6）：加视觉信号（面部表情 + 姿势）
- v2（M7-M12）：加生理信号（如有 wearable 接入）

## 8. Caveats（坦诚说明）

### 8.1 多模态信号解读存在系统性误差

这是技术现实。我们用多信号融合 + 长期趋势 + 主动询问兜底来缓解，但不完全消除。

**这个误差比问卷的误差小得多**：
- 问卷的误差是**系统性的**（社交期望、回忆偏差），无法用统计平滑
- 多模态的误差是**随机的**（噪声 + 个体差异），可被统计平滑

但要诚实承认：单次预测可能错；30 天累积概率才高度可信。

### 8.2 强化学习收敛速度

RL 需要密集反馈才能收敛。如果用户使用频率低（< 5 分钟/天），收敛会慢，意图预测能力提升曲线会变平。

**缓解策略**：
- 阶段 1（M0-M3）依赖合成数据加速训练，不等真用户
- 阶段 2 种子用户筛选时偏好"重度使用者"（每天 ≥ 60 分钟）
- 个体校准用 EMA（指数移动平均）让稀疏信号也能稳定更新

### 8.3 个体差异

同样的"嘴角上扬"在不同主人身上含义不同——L7 必须学每个主人的"信号-意图"映射。这意味着冷启动期（前 2 周）的预测准确率必然低，这是产品诚实声明：

> "前两周它对你的理解还在建立中，可能会有点笨拙——这是它认真在学你的过程"

不要承诺"开箱即用"，要承诺"两周后开始懂你"。

### 8.4 隐私与伦理边界

多模态感知本身就是隐私敏感的。本文档的所有评估机制必须依赖 §10.1 第 6 项"用户可治理"兜底：
- 主人可关闭任何模态（视觉/音频/IoT 单独 toggle）
- 主人可删除任何反馈采集窗口数据
- 主人可看见 AI 的预测和反馈解读（"我对你的新理解" + "记忆账本"）

如果这些治理能力没工程对应（见 §2.10 自检风险），整套评估机制不可启动。

### 8.5 关于"自我评估的元认知幻觉"

AI 用自己的能力评估自己——会不会有"我以为自己懂了但实际没懂"的元认知幻觉？

会有。这是不可消除的。缓解方式：
- 主动询问兜底（§5.6）作为元认知不确定性的对外信号
- 长期趋势监控（§5.4 关系深度维度）作为元认知失效的早期检测
- 老板每月人工抽样审计（5 个用户 × 5 个反馈窗口）作为最后兜底
